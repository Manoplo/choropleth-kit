## Bubbles

`variant="bubble"` draws a circle per datum. Its **area** follows `getValue`, and an optional second metric colors it.

```tsx
<ChoroplethMap
  {...common}
  variant="bubble"
  getValue={(s) => s.sales} // absolute value → circle area
  getColorValue={(s) => s.growth} // optional second metric → color
  getCoordinates={(s) => s.at} // [lon, lat]
/>
```

- `null` and values of zero or less draw no circle.
- Without `getCoordinates`, each bubble sits at its region's centroid.
- Bubbles scale with zoom according to `zoom.bubbleScaling`: `"sqrt"` (default), `"screen"` (constant on screen) or `"geo"` (grows with the map).
- The map exposes `sizeLegend`, the size reference circles, alongside the color legend.

## Microstates as dots

Countries too small to see in a 1:110m geometry (Andorra, Monaco…) can be given a coordinate:

```tsx
<ChoroplethMap
  {...common}
  fallbackPoints={{ AD: [1.52, 42.51], MC: [7.42, 43.73] }}
/>
```

A datum whose id joins no region but is listed there is painted as a dot with the datum's color. In `bubble`, it becomes a bubble. `choropleth-kit/geo` exports `worldFallbackPoints` with a ready-made list.

## Markers

Markers are HTML elements anchored to `[lon, lat]` that follow the map. Give them a look from the **preset**, or bring your own content.

:::note[Not in the published package yet]
The preset look (`shape`, `size`, `color`, `pulse`, `glow`, `showLabel`) and `tooltip` are in the library source and ship with its next version. Markers with your own `children` work today.
:::

### The preset look

With no `children`, any of the options below draws a shape instead of the default dot.

```tsx
<ChoroplethMap
  {...common}
  markers={[
    { id: "mad", coordinates: [-3.7, 40.4], label: "Madrid", shape: "pin", pulse: "always", glow: 6 },
    { id: "nyc", coordinates: [-74, 40.7], label: "New York", shape: "diamond", size: 14, color: "#e11d48" },
  ]}
/>
```

| Option        | Default                                   | Meaning                                                                          |
| ------------- | ----------------------------------------- | -------------------------------------------------------------------------------- |
| `shape`       | `"circle"`                                | `"circle"`, `"triangle"`, `"square"`, `"diamond"` or `"pin"`                     |
| `size`        | `12`                                      | Width of the shape in px (a pin is taller, in proportion)                        |
| `color`       | `--cm-marker-fill`                        | Any CSS color                                                                    |
| `stroke`      | `--cm-marker-stroke`                      | Outline color; `"none"` for no outline                                           |
| `strokeWidth` | `1.5`                                     | Outline width in px                                                              |
| `pulse`       | `"none"`                                  | A ripple: `"hover"` while the pointer is over the marker, `"always"` continuously |
| `glow`        | `0`                                       | Blur radius of an outer glow in px; `0` is off                                   |

A **pin** has its tip on the coordinate; the other shapes are centered. `anchor` still overrides that. The ripple stops with `prefers-reduced-motion`. A marker keeps its size at any zoom unless you set `scaleWithMap`.

### Labels

`showLabel` writes the marker's `label` beside it.

```tsx
{ id: "mad", coordinates: [-3.7, 40.4], label: "Madrid", showLabel: true, labelPriority: 1 }
```

- **The side is automatic.** Each label tries the right, then the left, top and bottom, and takes the first side where it does not cover another label or marker. If none fits, or the map's edge would cut it, the label is hidden. Zoom in and it returns.
- **`labelPosition`** (`"right"`, `"left"`, `"top"`, `"bottom"`) fixes the side; the label is then hidden if it collides, instead of moving.
- **`labelPriority`** decides who chooses first: higher wins, and ties go to the marker listed first.
- It is resolved on the real, measured boxes when a zoom or pan ends, never per frame. Marker labels avoid each other, but not the [region names](/guides/labels-and-i18n/) yet.

### Tooltip

```tsx
{ id: "mad", coordinates: [-3.7, 40.4], label: "Madrid", tooltip: true }              // shows the label
{ id: "nyc", coordinates: [-74, 40.7], tooltip: <><b>New York</b><div>28 stores</div></> }
```

The tooltip is anchored to the marker, not to the cursor. It appears on hover and on keyboard focus (a marker with a tooltip becomes focusable, and the tooltip describes it). It goes on top by default and, near an edge, slides or moves to a side that fits. `true` shows the `label`. It works with the preset shapes and with your own `children`, and it is separate from the map's own tooltip for regions.

### Your own HTML

```tsx
<ChoroplethMap
  {...common}
  markers={[
    { id: "hq", coordinates: [-3.7, 40.4], label: "Headquarters", children: <b>HQ</b> },
  ]}
/>
```

When you pass `children`, they are the marker and the preset options are ignored. These options apply to every marker:

| Option         | Default                                          | Meaning                                                                  |
| -------------- | ------------------------------------------------ | ------------------------------------------------------------------------ |
| `anchor`       | `"bottom"`; `"center"` for non-pin preset shapes | Which point sits on the coordinate: a pin's tip, or `"center"`           |
| `scaleWithMap` | `false`                                          | `false` keeps its size at any zoom; `true` grows with the map            |
| `clip`         | `true`                                           | Hide it when its coordinate leaves the map                               |
| `label`        | none                                             | Accessible name; without it the marker is decoration for assistive technology |

Markers are positioned with CSS from the camera variables, so panning and zooming re-render nothing, however many there are.

With the compound API, put `<Choropleth.Markers>` and `<Choropleth.Marker>` next to `<Choropleth.Svg>`. They are HTML, so they sit above the SVG.

## Region names

`regionLabels` writes region names on the map. Labels avoid overlapping, and zooming in reveals more. See [Labels and i18n](/guides/labels-and-i18n/).
